# Axon

**Root-cause analysis for cross-team failures, reasoned as Cypher over a FalkorDB company graph.**

When a dark store's delivery promise slips, the cause usually spans five teams: a broken chiller (Facilities), a product moved to a back freezer (Store Ops), and a campaign tripling demand for it (Growth). Axon starts from the alert, sends department agents into the graph in parallel, and comes back with the root cause, the amplifier, who to call, and a source for every claim. It then remembers the incident, so the next similar alert is faster.

> **All data is synthetic.** DashMart and FreshLoop are fictional companies; every person, message and ticket is generated by `seed/`. Nothing comes from a real company, Slack or Jira.

## What it does

1. **An alert fires.** For example, promise time at store SD-04 rose from 9.5 to 16 minutes, attributed to Probiotic Buttermilk.
2. **The orchestrator recalls memory** and dispatches department agents in one parallel round: Store Ops, Growth, and Facilities when memory says so.
3. **Each department runs its own model loop** over its own graph tools. Every tool call is one Cypher query, and every result is written back to the graph as a **Finding** that cites the exact nodes it touched.
4. **Departments build on each other through the graph.** Store Ops traces the move to the broken chiller; Facilities then checks that chiller's tickets and owner.
5. **The answer is validated.** A claim survives only if it cites Findings from this investigation. The root cause must be backed by a structural Finding (not keyword hits alone), and the amplifier must be a campaign.
6. **The incident is written back as memory.** An episodic memory records what happened, and a procedural one records where to look first next time.

In the workbench (`/app`), the graph renders Obsidian-style: the orchestrator links only to the department sub-brains, each sub-brain links only to the data it queried, and dashed links show which department built on which. Every queried edge gets a beam of light; parallel calls fire parallel beams, and queried edges keep glowing. Every step reads as a sentence and can expand to show the real Cypher it ran, with a plain-English gloss.

## Quick start (local)

Requirements: Docker, Python 3.13, Node 20.19+.

```bash
git clone https://github.com/aadijaiin/GraphRCA.git && cd GraphRCA
docker compose up -d falkordb                       # FalkorDB on :6379 (browser UI on :3000)
python3 -m venv .venv && source .venv/bin/activate
pip install -r backend/requirements.txt
python seed/generate.py                             # graph 'dashmart' (365 nodes, 957 edges), deterministic
python seed/generate.py --tenant freshloop          # second tenant, for isolation

cd backend && uvicorn app:app --port 8000           # API (terminal 1)
cd frontend && npm ci && npm run dev                # UI on http://localhost:5173/app (terminal 2)
```

Or from the terminal: `cd backend && python investigate_cli.py ALT-001`. Tests: `cd backend && pytest -q tests` (72 tests, no network).

**Choose the model** by copying `.env.example` to `.env`; it is gitignored and read by the API, CLI and Docker:

| Backend                | Settings                                            | Notes                                                                                                                         |
| ---------------------- | --------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Server model (default) | `LOCAL_MODEL_URL`, `LOCAL_MODEL_KEY`, `LOCAL_MODEL` | Any OpenAI-compatible endpoint. Tested with `openai/gpt-oss-20b` on build.nvidia.com (free key) and works with Ollama or vLLM |
| Claude                 | `ANTHROPIC_API_KEY`                                 | `claude-opus-5-5` via the Anthropic SDK                                                                                       |
| Scripted               | none                                                | Deterministic policy with the same tools and graph writes; used by tests and as an offline fallback                           |

The UI's model dropdown lists the backends this server has configured. Full step-by-step setup, expected output for every command, and troubleshooting are in [`docs/RUNBOOK.md`](docs/RUNBOOK.md).

**Deploying:** `docker compose --profile app up -d --build` runs FalkorDB plus one container that serves the API and the built UI on :8000. Any container host works; point it at FalkorDB with `FALKORDB_HOST` and `FALKORDB_PORT` (plus `FALKORDB_USERNAME` and `FALKORDB_PASSWORD` for FalkorDB Cloud).

## Graph data model

One FalkorDB graph per tenant (`dashmart`, `freshloop`). Agent state lives in the same graph as the data it cites, because FalkorDB has no cross-graph edges. Full property list: [`docs/schema.md`](docs/schema.md).

```
(Supplier)-[:SUPPLIES]->(SKU)<-[:STOCKS]-(Store)-[:HAS_EQUIPMENT]->(Equipment)<-[:ABOUT]-(Ticket)
(Campaign)-[:PROMOTES]->(SKU)          (Campaign)-[:TARGETS]->(Store)
(Decision)-[:CHANGED {from,to}]->(SKU) (Decision)-[:AT]->(Store)   (Decision)-[:MADE_BY]->(Person)
(Decision)-[:BECAUSE_OF]->(Ticket|Equipment)
(Alert)-[:AT]->(Store)                 (Alert)-[:INVOLVES]->(SKU)
(Person)-[:OWNS]->(Campaign|Ticket|Equipment|Supplier)   (Person)-[:WORKED_ON]->(Equipment|Ticket|SKU)
(Artifact)-[:EVIDENCE_FOR]->(Decision|Ticket|Campaign|Alert)   (Artifact)-[:AUTHORED_BY]->(Person)

Agent layer:
(Investigation)-[:TRIGGERED_BY]->(Alert)
(Task {department})-[:PART_OF]->(Investigation)
(Finding {agent, tool, summary})-[:PART_OF]->(Investigation)   (Finding)-[:CITES]->(any node)
(Memory:Episodic|Procedural)-[:LEARNED_FROM]->(Investigation)   (Memory)-[:ABOUT_ENTITY]->(any node)
(Memory)-[:SUPERSEDES]->(Memory)
```

| Label     | Count (dashmart) | Label                              | Count |
| --------- | ---------------- | ---------------------------------- | ----- |
| Person    | 30               | Ticket                             | 40    |
| Store     | 6                | Decision                           | 25    |
| SKU       | 60               | Artifact (Slack, SOP, ticket text) | 150   |
| Equipment | 24               | Alert                              | 10    |
| Supplier  | 8                | Campaign                           | 12    |

The seed plants ten incidents with ground truth in `eval/incidents.json`. It also plants distractors: the same SKU moved in another store, ended and paused campaigns, an already-fixed chiller, and messages that match the right keywords but belong to the wrong incident. Answering correctly therefore takes graph structure, not keyword search.

## Cypher queries and graph algorithms

Every query the product runs is a file in [`queries/`](queries/), loaded at runtime. No agent writes Cypher; agents choose among these parameterized tools. The workbench shows each one with a plain-English gloss ("What it asked the graph").

| Query                                                                               | Used by      | What it asks the graph                                                                                                          |
| ----------------------------------------------------------------------------------- | ------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| `trace_decision`                                                                    | Store Ops    | Latest decision that moved the alert's SKU **in the alert's store** before the alert, its author, causes, assignee and evidence |
| `find_amplifiers`                                                                   | Growth       | Active campaigns that promote that SKU, target that store, and started before the alert, with owners                            |
| `equipment_status`                                                                  | Facilities   | A store's equipment, owners and tickets, flagging open unassigned ones                                                          |
| `find_expert`                                                                       | Facilities   | People ranked by work on an entity, directly or via tickets about it                                                            |
| `impact_of`                                                                         | Supply       | Supplier → SKUs → stores, plus active campaigns on them (what a delay breaks)                                                   |
| `connect_path`                                                                      | Orchestrator | Shortest path in either direction, using the **`algo.SPpaths`** algorithm                                                       |
| `rank_people`                                                                       | Orchestrator | Who owns the incident: incident-local degree with **`algo.pageRank`** as the tie-break                                          |
| `recall_memory`                                                                     | Orchestrator | Similar past incidents (same metric, same SKU category) ranked by similarity, with their learned plans                          |
| `read_findings`                                                                     | All agents   | The shared state: every Finding of this investigation                                                                           |
| `search_artifacts`                                                                  | All agents   | Full-text search over Slack, SOP and ticket text and SKU names (**FalkorDB full-text indexes**)                                 |
| `alert_context`, `get_artifacts`, `finding_sources`, `node_brief`, `ticket_subject` | Code         | Alert context, citations, and validator lookups                                                                                 |
| `w_*.cypher`                                                                        | Code         | Writes: Investigation, Task, Finding, Memory, ingested events (one atomic query each)                                           |
| `00_schema.cypher`                                                                  | Seed         | Range indexes on `id` and full-text indexes; unique constraints on every label                                                  |

## Architecture

```
React UI (/app) ──SSE──> FastAPI ──> Orchestrator ──dispatch([tasks]) in parallel──> Store Ops / Growth / Facilities / Supply
                                          │                                              │
                                          └──── tools = queries/*.cypher ─── FalkorDB ───┘   (also exposed over MCP)
```

- **Agents:** `backend/agents.py` has one generic runner; each agent is a prompt plus a tool subset. Backends are in `backend/llm.py`.
- **Shared state:** `backend/state.py` writes the Investigation, Task, Finding and Memory nodes.
- **Ingestor:** `backend/ingestor.py` validates a pasted message against the graph and writes it in one atomic query. An alert-shaped message creates an Alert, which the orchestrator then investigates (`POST /api/events`).
- **MCP:** `backend/mcp_server.py` exposes the same tools to any MCP client.
- **Contracts:** `docs/schema.md`, `docs/tool_contract.md`, `docs/events.md`. Decisions and their reasons are in `DECISIONS.md`.

## How each track is met

- **Track 03, Company Brain:** messages, tickets, decisions, people and equipment live in one graph. The graph answers who owns and who knows what (`find_expert`, `rank_people`), traces decisions to their source messages, keeps knowledge current through the Ingestor, and backs every answer with sources.
- **Track 02, Agent Memory and Coordination:**
  - episodic and procedural memory as graph nodes, with superseding;
  - measured effect: ALT-005 takes 1 dispatch round after ALT-001 instead of 2;
  - department agents coordinate only through Task and Finding nodes;
  - one graph per tenant, with isolation tests.
- **Track 01, Agents That Act on Connected Data:** graph queries and algorithms (`algo.SPpaths`, `algo.pageRank`, full-text) are the agents' tools, also served over MCP. Answers end in concrete actions with owners, such as "assign FAC-882 to Rajesh Nair" or "pause Summer Coolers for SD-04".

## Honest notes

- The ten incidents are synthetic, so results on them are illustrative, not a benchmark.
- With gpt-oss-20b, answers vary run to run. The validator and the graph-bound tools catch the mistakes we have seen (`backend/tests/test_model_mistakes.py`).
- The free hosted endpoint sometimes stalls. Calls time out after 60 s with two retries, and the scripted backend is the labelled fallback.
